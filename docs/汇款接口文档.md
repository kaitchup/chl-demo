<a id="doc-intro"></a>
## 文档说明
- 服务器地址：`https://openapi.upay-test.best`。
- 接口请求方式：全部为 `POST`。
- 成功响应约定：`code = 0`、`success = true`。
<a id="common-headers"></a>
## 通用请求头
| Header | 必填 | 说明 | 示例 |
| --- | --- | --- | --- |
| `X-UPA-REQUESTID` | 是 | 请求唯一码(最大长度64个字符) | `req_20260924_0001` |
| `X-UPA-TIMESTAMP` | 是 | 请求时间戳(毫秒) | `1727136000000` |
| `X-UPA-APIKEY` | 是 | API KEY | `upa_live_xxxxxxxxxxxx` |
| `X-UPA-SIGN` | 是 | 签名后的字符串 | `base64-signature-string` |

<a id="common-response"></a>
## 通用响应结构
| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `code` | `integer` | 是 | 状态返回码，code=0 表示成功 |
| `msg` | `string` | 是 | 状态描述 |
| `success` | `boolean` | 是 | 是否请求成功(true=成功,false=失败) |
| `ts` | `integer` | 是 | 服务器响应时间(Unix 时间戳，秒) |

通用成功响应示例：
```json
{
  "code": 0,
  "msg": "success",
  "success": true,
  "ts": 1727136000
}
```

## 2. 新增收款人
- 模块：`收款人`
- 方法：`POST`
- 路径：`/api/v1/payout/beneficiary/add`
- 参数加密：是
- 验签：是
- 接口描述：功能描述: 新增收款人。  前置条件: 1. 需要签名 2. 参数需要加密 3. subject 仅支持 person 或 enterprise

### 请求参数说明
请求头见上文“通用请求头”，请求体字段如下：
| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `subject` | `string` | 是 | 主体(person=个人,enterprise=企业)；可选值: person, enterprise |
| `formData` | `string` | 是 | 表单数据(JSON格式字符串) |

### 请求示例
```json
{
  "subject": "person",
  "formData": "{\"code\":\"person\",\"group\":[{\"code\":\"base\",\"fields\":[{\"fieldKey\":\"name\",\"fieldValue\":\"Zhang San\"},{\"fieldKey\":\"dateOfBirth\",\"fieldValue\":\"1000742400000\"}]},{\"code\":\"contact\",\"fields\":[{\"fieldKey\":\"email\",\"fieldValue\":\"zhangsan@gmail.com\"}]},{\"code\":\"document\",\"fields\":{\"0\":[{\"fieldKey\":\"type\",\"fieldValue\":\"id_card\"},{\"fieldKey\":\"number\",\"fieldValue\":\"ID202409240001\"}]}}]}"
}
```

| `success` | `boolean` | 是 | 是否请求成功(true=成功,false=失败) |
| `ts` | `integer` | 是 | 服务器响应时间(Unix 时间戳，秒) |
| `data` | `object` | 否 |  |
| `data.beneficiaryNo` | `string` | 是 | 收款人编号 |

### 响应示例
```json
{
  "code": 0,
  "msg": "success",
  "success": true,
  "ts": 1727136000,
  "data": {
```

## Webhook说明
### 汇款订单状态变更
当汇款订单状态发生变更时，系统会向代理商配置的 webhook 地址发起 `POST` 推送。

推送报文 `Content-Type` 为 `text/plain`，HTTP 请求体为加密字符串。以下示例为解密后的明文 JSON 结构，其中 `detail` 字段为 JSON 格式字符串，接收方需在解密后继续解析 `detail`。

### 推送示例
```json
{
  "event": "PO_ORDER_STATUS_CHANGE",
  "trace": "TRACE202609250001",
  "orderNo": "WH202609250001",
  "timestamp": 1727229600000,
  "detail": "{\"payerNo\":\"PAY202609240001\",\"bankAccountNo\":\"BANK202609240001\",\"orderNo\":\"ORD202609240001\",\"status\":7}"
}
```

### 推送参数说明
| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `event` | `string` | 是 | 事件标识，固定为 `PO_ORDER_STATUS_CHANGE` |
| `trace` | `string` | 是 | 本次 webhook 推送的链路追踪号 |
| `orderNo` | `string` | 是 | 本次 webhook 通知唯一订单号，对应 `payout_agent_webhook.thirdOrderNo`，不是汇款业务订单号 |
| `timestamp` | `integer` | 是 | 推送时间戳，毫秒 |
| `detail` | `string` | 是 | 业务明细，JSON 格式字符串，解析后结构见下表 |

### `detail` 参数说明
| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `detail.payerNo` | `string` | 是 | 付款人编号 |
| `detail.bankAccountNo` | `string` | 是 | 银行账户编号 |
| `detail.orderNo` | `string` | 是 | 汇款业务订单号，对应 `payout_order.order_no` |
| `detail.status` | `integer` | 是 | 订单变更后的状态(1=报价中,2=待确认报价,3=报价已确认,4=报价失败,5=审核中,6=汇款处理中,7=汇款成功,8=汇款失败,9=已取消,10=退款处理中,11=已退款,12=待确认新报价) |
