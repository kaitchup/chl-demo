# UPay 收单 API 对接问题汇总

## 总结

当前支付 API 对接测试阶段存在多项阻塞与缺失问题，收款、Webhook、账务全流程均无法完整验证，共 2 个 P0、3 个 P1、3 个 P2 待跟进；另有 2 个 P0 已解决（见「已解决」）。

## 问题清单

### 🔴 P0 — 阻塞

1. 测试环境缺少公网域名，VPS 上的服务无法完成从发单到到账的全流程测试。
2. 测试环境不支持真实链上交易入账（模拟到账仅开发环境可用），真实到账全流程仍无法验证。

### 🟠 P1 — 高

1. 缺少退款接口，商户收款被 KYC / AML 卡住时无途径发起退款。
2. 缺少账务推送和账务分页查询接口。
3. 查询接口不返回 `expires_at`，且过期不反映在 `status`，商户轮询时无法发现订单已超时，会持续把用户导入静默拒付的收银台（详见下方「详细问题与解决方案 §1」）。

### 🟡 P2 — 中

1. 缺少通过商户方订单 ID 查询支付详情的接口，订单超时或出错时商户侧不可见。
2. API 文档中生产环境 URL 和沙盒环境 URL 均有误。
3. 文档列出创建、列表、查询、取消四个接口，实际仅有创建和查询两个，缺少列表和取消。

## 已解决

- (原 P0) 开发管理后台缺少模拟到账 mock 接口，Webhook 及账务流程无法对接调试 —— **2026-06-04 已解决**：开发环境新增模拟到账能力，可手动触发到账以驱动 Webhook / 对账 / 开通全流程。
- (原 P0) 开发环境收银台生成虚拟地址而非真实钱包地址，无法完成付款入账 —— **2026-06-04 已解决（限开发环境，经模拟到账）**：开发环境可通过模拟到账完成付款入账验证。已实测订单 `sub_efd08ae184dc49a6e79d06a29ba10b0b`（discount5 / 5.00 USD）经模拟到账由 PROCESSING → SUCCEEDED，会员开通成功。注：此为**开发环境**模拟入账；**测试环境**仍需真实链上交易入账、目前不支持，见上方 P0「测试环境不支持真实链上交易入账」。

## 详细问题与解决方案

### §1 超时订单商户侧不可发现，用户仍能进入静默拒付的收银台 (P1)

**现象**

- 订单生命周期 status 只有 4 态：INITED / PROCESSING / SUCCEEDED / CANCELED，**过期不再是独立 status**（设计上：链上到账是唯一权威，过期单链上晚到仍会入账，故不杀单）。
- 查询接口 `GET /v1/payment/request/{id}` 的响应**不包含 `expires_at`，也不包含 `checkout_url`**（实测仅返回 id / merchant_id / merchant_order_id / amount / currency / status / description / created_at / metadata）。
- 两者叠加 → 只靠轮询查询接口的商户，过期后 `status` 仍停在 PROCESSING，响应里又拿不到 `expires_at`，**在轮询阶段拿不到任何「已超时」信号**。

**影响**

- `expires_at` 只能在创建订单的 POST 响应里拿到。商户若未在下单时持久化它，就永远无法判断订单是否过期。
- 常规接入姿势（只存 payment_id、靠查询接口拿最新状态）会直接掉坑：持续把用户导入一个已过期、收银台静默拒付的支付页，用户看到空白/无法支付，商户侧却显示「待支付」。本项目 chl-demo 已实际踩中。

**解决方案（按权威性强弱）**

1. **数据层（根因，最该做）**：`GET` 响应补 `expires_at`，并增加网关算好的派生字段 `expired: true/false`（或 `payable`）。让商户不依赖「是否存过创建响应」即可权威判断。注意此为**派生展示字段，不要并入 status 枚举**，以免破坏「过期可恢复、链上晚到仍入账」的语义。
2. **收银台层（兜底，必须有）**：收银台页面及 `bootstrap` / `status` 接口对过期单返回**机器可读**信号（如 `status:"expired"` 或 HTTP 410），而非空白页；即便商户未拦截、把用户送入，也能呈现「订单已过期，请重新下单」并让商户跳转封装据此回退。
3. **文档层**：把隐式契约写成显式红字——「status 不表达过期；过期判定 = 商户本地比较 `expires_at`（须在创建响应里持久化）；过期后不得再向用户暴露 `checkout_url`」，并配示例代码 + 接入 checklist 勾选项。
4. **QA 层**：upay-qa 增用例（关联 TODO `UT-OA-02 过期时间戳`）——建短有效期订单 → 等过期 → `GET` → 断言商户可判出过期（响应含 `expires_at`/`expired`，或收银台返回过期信号），形成回归护栏。

**商户侧参考接入姿势（chl-demo 范本）**

- 下单即持久化 `expires_at`；
- UI 中 `PENDING/PROCESSING + now > expires_at + received_amount == 0` → 视为不可付，并隐藏「继续支付」/不再暴露 `checkout_url`；
- **继续轮询不停**（防链上晚到仍能入账），仅在「是否引导进收银台」这一步拦截——拦入口，不拦对账。
